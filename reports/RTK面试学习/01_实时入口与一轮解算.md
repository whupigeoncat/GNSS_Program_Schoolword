# 第 1 讲：从选择实时模式，到得到一行 RTK 结果

本讲只解决“程序整体怎样跑起来”。解码每个字节、MW/GF 推导、B/W/R 矩阵和 LAMBDA 搜索，在后面分别精读。

## 1. 先能用自己的话描述程序

> 我的程序通过两条 TCP 连接分别接收基站和流动站的 OEM7 二进制数据。共用一套解码逻辑，两站分别维护字节缓冲和观测历元，共享广播星历。取得满足时间差阈值的一对观测历元后，形成站间单差并检查相位连续性，再用 SPP 提供流动站初值和卫星中间结果，分系统选择参考星，建立双差模型求浮点解。当前实时配置使用 EKF，然后调用 LAMBDA 尝试固定整数模糊度。通过固定检验则输出固定解，否则输出成功的浮点解。最终把基线加到基站坐标，得到流动站坐标。

这段话对应真实实现。不要扩展成“任何时候都是固定解”“双差消除全部误差”“实时模式就是 EKF”等超出代码的说法。

## 2. 三种“模式”分别管什么

| 层次 | 控制项 | 当前值 | 含义 |
|---|---|---|---|
| 程序入口 | 控制台 `mode` | 选择 `3` | 进入 RTK 实时分支 |
| 数据源 | `cfg.IsFileData`，来自 `FROM FILE OR COM` | `2` | TCP 数据源；main 实时分支会检查 |
| 参数估计 | `cfg.RTKProcMode`，来自 `RTK PROCESSING MODE` | `1` | RTKProcEpoch 调用 RTKFilter |

菜单 0/1 是 SPP 文件/实时；菜单 2/3 是 RTK 文件/实时。当前文件配置 `rtk.cfg` 选择 LSQ，即 `RTKProcMode=2`；实时配置 `rtk_rt.cfg` 选择 EKF，即 `RTKProcMode=1`。这是两份配置当前的选择，不是文件/TCP 与 LSQ/EKF 的必然绑定。

代码实际分支是：`RTKProcMode == 1` 时滤波，否则最小二乘。不要把它说成程序严格拒绝了所有其他模式数值。

main 顶部的 `GPS_MODE/FREQ_MODE/TROPO_ENABLE` 主要服务于复用的 SPP 部分；RTK 的频率映射和噪声使用有自己的代码，不能仅凭这几个全局变量概括整个 RTK 策略。

## 3. 进入 main.cpp:293 的实时分支

### 3.1 读配置：295—310 行

```cpp
ROVERCFGINFO cfg;
char cfgName[256] = "rtk_rt.cfg";
cin.ignore((numeric_limits<streamsize>::max)(), '\n');
cin.getline(cfgName, 256);
if (cfgName[0] == '\0') strcpy_s(cfgName, "rtk_rt.cfg");
if (!ReadRTKConfigInfo(cfgName, cfg)) return 1;
```

`cin >> mode` 读取数字后，会留下换行符；`ignore` 把这一行剩余内容读掉，避免后面的 getline 直接读到上次输入的换行。用户直接回车时 getline 得到空字符串，所以要再写回默认文件名。

`ReadRTKConfigInfo` 把文本内容写进 `cfg`。这不是每个历元都重新读取：它在循环外读取一次，之后各历元使用同一个配置对象。

默认文件名是相对路径，寻找位置是**进程的当前工作目录**。它不由源码文件所在目录自动决定，也不必然等于 exe 所在目录。

```cpp
if (cfg.IsFileData != 2) return 1;
ELV_CUTOFF = cfg.ElevThreshold;
```

实时入口要求数据源值为 2。高度截止角通过全局变量交给复用的 SPP 等逻辑；配置单位是度，涉及三角函数时还要转弧度。

### 3.2 建输出文件和双连接：312—326 行

```cpp
ofstream rtkrt("RTK_RT.txt");
SOCKET BasSock, RovSock;
OpenSocket(BasSock, cfg.BasNetIP, cfg.BasNetPort);
OpenSocket(RovSock, cfg.RovNetIP, cfg.RovNetPort);
```

这里是便于说明的摘录，原代码用 `if` 与 `||` 检查两个 OpenSocket 的返回值。

两条连接分别运送基站/流动站数据。TCP 提供字节流，应用层的 OEM7 帧边界仍要自己识别；一次 recv 不等于一个观测历元，也不保证恰好一个完整消息。

`ofstream` 默认以覆盖方式打开 RTK_RT.txt；重复演示会覆盖上次同名结果。文件路径同样相对于当前工作目录。`POSITION RESULT FILE` 虽然被配置解析器读入，但当前 main 实际使用的是这个硬编码文件名。

`OpenSocket` 的实现未检查 connect 的返回值，因而不能把“OpenSocket 返回 true”等同于“连接必定成功”。它是需要认识的实现问题，见 02 易误读项；本轮未修改程序。

### 3.3 创建长期数据对象：328—330 行

```cpp
RAWDAT* Raw = new RAWDAT();
InitNovDecoder(&Raw->BasDec, 0);
InitNovDecoder(&Raw->RovDec, 1);
```

`Raw` 是指向堆上 RAWDAT 对象的指针。`Raw->BasDec` 表示访问该对象内的 BasDec 成员；`&Raw->BasDec` 是取得该成员的地址，让函数直接修改这份成员。

这里只创建一个 RAWDAT 对象，放在循环外。它跨历元存在，所以不仅能存当前观测，还能保存未解完的字节、基站固定坐标以及 EKF 历史状态。

使用 new 的直接效果是让这个较大的对象占用堆空间。不要仅凭写法推断作者一定出于某种动机；能解释实际效果即可。正常退出路径末尾有 `delete Raw`。

两份 decoder 的主要区别是各自的 Buff/Len/统计状态。`SourceId=0/1` 是来源标记，当前消息解析并不是靠它自动挑选 BasEpk/RovEpk；真正的目标对象由调用者传入。

## 4. RAWDAT 是整条流水线的共同载体

| 成员 | 放的是什么 | 主要写入者 | 主要读取者 |
|---|---|---|---|
| `BasDec/RovDec` | 两站原始字节缓冲、有效长度、统计 | FeedNovData、ParseNovMsg | PumpStream、下一次解码 |
| `BasEpk/RovEpk` | 两站当前观测时间、卫星 P/L 等 | RANGEB 解码；随后补卫星中间量 | 配对、单差、SPP、相对定位 |
| `GpsEph/BdsEph` | 两流共用的广播星历数组 | 星历消息解码 | 卫星轨道/钟差计算 |
| `BasPos/BasPosValid` | 首个被接受的基站 BESTPOS XYZ 及可用标志 | GetSynGNSSObs | 近似初值、固定基站几何、输出 |
| `SdObs` | 当前两站共视卫星的单差与质量标记 | FormSDEpochObs、DetectCycleSlip | 选参考星、浮点解 |
| `DDObs` | 参考星、双差数量、固定状态和固定结果 | DetRefSat、浮点解、RTKFix | main、下一历元滤波相关处理 |
| `FloatRes` | 浮点模糊度、基线、协方差、精度指标 | RTKFloat 或 RTKFilter | RTKFix、main |
| `Ekf` | 跨历元滤波状态、协方差和参数对应信息 | RTKFilter | 下一次 RTKFilter |

共享星历与独立观测并不矛盾：这里两站接收的是同类广播星历，而各站原始字节、观测时刻和观测值必须分开保存。当前主程序是一个线程顺序读取两条流，不是两个线程并行解算。

## 5. while 的第一道门：有没有可用的配对历元

main.cpp:334：

```cpp
int s = GetSynGNSSObs(BasSock, RovSock, Raw);
if (s < 0) break;
if (s == 0) continue;
```

| 返回值 | 当前实时实现中的含义 | main 的处理 |
|---|---|---|
| `-1` | 参数/socket 无效，或 select/读取发生错误、断开等 | 跳出 while，关闭连接并释放 Raw |
| `0` | 在追基站历元时等待 200 ms 超时 | 本次不解算，进入下一轮调用 |
| `1` | 两站时间差满足配置在代码中的同步阈值 | 继续单差和 RTK |

`continue` 跳到当前 while 的下一轮；`break` 离开当前 while。两者不能混淆。

这是“本次调用返回了什么”的含义，不代表 GetSynGNSSObs 总能在固定时间内返回。例如等待流动站的内部循环在无数据但连接未报错时会继续等。

成功配对不代表时间完全相等。当前头文件设置文件阈值 0.5 s、实时阈值 5.0 s。比较的是解码出的观测时间差：

```cpp
dt = GetDiffTime(&Raw->RovEpk.Time, &Raw->BasEpk.Time);
```

不是网络接收耗时。`dt > 0` 表示流动站观测比基站晚；`dt < 0` 表示流动站早。5 秒是当前实现接受的时间差界限，不是“每 5 秒定位一次”，也不表示当前程序做了异步观测的插值校正。

本讲把同步函数看作一个接口，后续用时间轴把它的追赶分支逐句跑一遍。

## 6. 第二道门：从同步观测形成单差并标记相位质量

main.cpp:349—352：

```cpp
FormSDEpochObs(&Raw->BasEpk, &Raw->RovEpk, &Raw->SdObs);
DetectCycleSlip(&Raw->SdObs);
```

第一句按“同系统、同 PRN”配两站的卫星，再按相同频率求差：

```text
dP[f] = P_rover[f] - P_base[f]
dL[f] = L_rover[f] - L_base[f]
```

例如 G08 在流动站是第 3 项、在基站是第 7 项：它们仍是同一颗卫星，所以要保存 `nRov=3`、`nBas=7`，不能按两站相同数组下标直接相减。

第二句在单差上做 MW/GF 的历元间变化检查。注意单差形成函数本身已经检查半周标记和 LockTime 回退；不是只有 DetectCycleSlip 才做相位质量检查。

后续主要筛选条件是 `sd.Valid == 1`，所以“观测里有这颗星”和“这颗星能参与双差解算”是不同条件。

## 7. 第三道门：RTKProcEpoch 成功了吗

main.cpp:363—364：

```cpp
PPRESULT RovRes;
if (RTKProcEpoch(Raw, &cfg, &RovRes)) { ... }
```

`RovRes` 每轮新建，用于承接本轮流动站 SPP 的位置等结果。它不是最终 RTK 固定解容器。

真正的 RTK 结果放在 `Raw->FloatRes` 与 `Raw->DDObs`。函数返回 bool 是流程状态，复杂结果通过传入对象地址写回。

到 RTK_RelPos.cpp:300 看内部：

1. **基站坐标准备好了吗？** `BasPosValid == false` 直接失败。
2. **清除旧卫星位置有效标志。** 避免把上一轮的 SatPVT 当作本轮成功计算结果。
3. **检查两站观测粗差。** 调用两次 DetectOutlier。
4. **为流动站 SPP 设置近似初值。** 把基站 XYZ 放入 RovEpk.Pos，随后实际运行流动站 SPP；不是直接把两站当成同一点输出。
5. **SPP 成功了吗？** 失败则本轮 RTK 结束；成功时取得流动站位置和相关卫星中间量。
6. **计算基站历元的卫星位置。** 使用已知基站 XYZ 与基站自己的观测时间/伪距。
7. **选参考星。** GPS、BDS 分别选择；两个系统都没选出时失败。
8. **求浮点解。** 当前实时配置调用 RTKFilter；另一分支调用 RTKFloat。
9. **浮点成功后尝试固定。** 调用 RTKFix。
10. **返回浮点解是否成功。** 即使 RTKFix 返回 false，仍然可以返回 true。

因此要区分三层状态：

```text
GetSynGNSSObs 返回 1：有满足阈值的一对观测
RTKProcEpoch 返回 true：本轮浮点解成功
DDObs.bFixed 为 true：本轮还通过了固定流程
```

没有固定解不等于 RTKProcEpoch 失败；有数据也不等于有浮点解。

## 8. main 怎样选择最终结果

main.cpp:366—371：

```cpp
RTKFLOATRES& fr = Raw->FloatRes;
DDCOBS& dd = Raw->DDObs;
bool bFix = dd.bFixed;
const double* pBest = bFix ? dd.dPos : fr.dPos;
const double* nBest = bFix ? dd.dNeu : fr.dNeu;
```

`fr`、`dd` 是引用，相当于这两个成员的别名，不会再复制整份结构体。三目表达式 `条件 ? A : B` 在条件成立时选 A，否则选 B。

`pBest` 指向被选中的三元素 XYZ 基线数组；`nBest` 指向对应 NEU 基线数组。`const double*` 表示通过此指针只读数值，不妨碍上游通过其他途径更新原对象。

输出基线的符号是：

```text
baseline_xyz = rover_xyz - base_xyz
rover_xyz    = base_xyz + baseline_xyz
```

所以 main.cpp:374 的加法是从相对位置恢复流动站绝对位置，不是另做一次定位。`dPos` 在这里是完整基线，不是本轮迭代的坐标改正量。

基线的 NEU 是以基站为原点、按基站当地坐标轴表达的位移，不能叫“NEU 定位误差”。真正误差还要与参考坐标作差。

## 9. 终端每一项表示什么

```text
Bas ... sat=... | Rov ... sat=... | dt=... | BasePos OK
RTK week sow FIX/FLOAT ratio=... Ref(G/C)=... DD(G/C)=... amb=...
Baseline XYZ(m): ... | NEU(m): ...
Rover XYZ(m): ...
Rover BLH(deg,deg,m): ...
sigmaH=... sigmaU=... 或 sigmaXYZ=...
```

| 输出项 | 读法与限制 |
|---|---|
| `Bas/Rov sat` | 解码观测中的卫星项数；不是最终参与 RTK 的数量 |
| `dt` | 流动站观测时间减基站观测时间，秒 |
| `BasePos OK` | 已存入一个成功 BESTPOS 坐标；不等同于经过独立精度认证 |
| `FIX/FLOAT` | 本轮按 bFixed 选择的结果类型 |
| `ratio` | LAMBDA 次优候选代价 / 最优候选代价；代码有接近零分母的特殊处理 |
| `Ref(G/C)` | GPS/BDS 参考星 PRN，C 表示北斗 |
| `DD(G/C)` | 实际参与构造双差的非参考卫星数量，按系统统计 |
| `amb` | 双差模糊度参数数；一颗非参考星的两个频率都可用时贡献 2 个 |
| `Baseline XYZ` | 地固坐标系中流动站相对基站的基线，米 |
| `NEU` | 同一基线在基站当地坐标系的 N/E/U，米 |
| `Rover XYZ` | 加回基站坐标后的流动站地固坐标，米 |
| `Rover BLH` | 纬度、经度、椭球高；代码输出前将角度由弧度转成度 |
| `sigmaH/sigmaU` | 固定后协方差导出的水平/垂直形式精度 |
| `sigmaXYZ` | 浮点位置协方差导出的 X/Y/Z 形式精度 |

形式精度由模型及其噪声假设给出，不是与外部真值比较后的实测误差。输出 9 位小数也不等于具有相应的实际精度。

## 11. 循环何时结束

通信错误导致同步函数返回负数，或写结果文件失败时，main 跳出 while，然后调用两次 CloseSocket、delete Raw 并返回。

正常接收时一直处理新数据。当前代码没有实现自动重连或优雅的键盘退出逻辑；不要在面试介绍时声称具备这些功能。控制台强制中断也不能与执行到 while 后面的清理路径等同。

## 13. 本讲自检及参考回答

1. **RTK 为什么仍然调用 SPP？** 为流动站提供近似坐标，并生成后续几何计算与参考星选择需要的卫星中间量；最终展示的 RTK 坐标来自双差浮点/固定基线。
2. **两站各用一套解码代码吗？** 共用函数实现，但各有解码上下文与观测对象；调用时传入不同成员地址。
3. **RTKProcEpoch 返回 true，就一定固定了吗？** 不一定，表示浮点解成功；是否固定看 DDObs.bFixed。
4. **固定失败为什么还能输出？** 浮点解仍然是有效的本轮估计，main 会选择 FloatRes 中的基线。
5. **实时的 5 秒是接收超时吗？** 不是，是 PairEpoch 接受的两站观测时间差阈值；select 等待使用的是另外的毫秒参数。
6. **RovRes、FloatRes、DDObs 分别放什么？** SPP 结果、RTK 浮点结果、参考星及固定相关结果。
7. **为什么先算基线再加基站坐标？** 当前结果约定基线为流动站减基站，加回已知基站坐标即可恢复流动站 XYZ。
8. **为什么 RAWDAT 在循环外，RovRes 在循环内？** Raw 需要保存跨历元的缓冲、基站坐标和滤波历史；RovRes 在当前调用中承接本轮 SPP。

能对着代码解释这些问题，再进入下一讲的数据结构、数据输入和同步细节。
